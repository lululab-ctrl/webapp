This application was built entirely in HTML, CSS, and vanilla JavaScript with a Supabase (PostgreSQL) backend — no framework, no build step, deployed as a single portable file. It demonstrates end-to-end product thinking: multi-role permission systems, live data sync, file storage integration, audit-safe workflows, and a fully custom-designed interface.

Changes made by one person appear instantly for everyone else logged in, with no page refresh required.

Developed iteratively over dozens of feature rounds in direct collaboration with the end client, the project reflects hands-on experience across the full stack: relational database design, real-time architecture, role-based access control, cloud file storage, and a polished, purpose-built interface.

Five distinct roles, each scoped to exactly the features they need:
Staff — daily entries, leave requests Admin — full roster & approval control Treasurer — team funds management IPS — performance scoring QA — incident tracking & disputes

Dual-role support allows any account to hold a primary role plus an optional second role (e.g. a Treasurer who is also QA) without needing a separate account. Named super-user exceptions layer additional control on top of the role system.

Real business logic — not a CRUD demo.

Designed for a real short-term rental property management business, this system replaces manual spreadsheets with a secure, real-time, multi-user platform that handles employee payroll tracking, client billing, and operational data management — all with zero server maintenance cost.

The application is built entirely in vanilla JavaScript without React, Vue, or any UI library, demonstrating deep language fundamentals. It's a production-grade database design — proper use of upsert/dedup patterns, paginated reads, WebSocket subscriptions, and race condition handling. It models actual payroll workflows, billing groupings, and multi-user audit trails.

Deployed and live — not a local prototype — running in production for a real business on GitHub Pages with a cloud database backend. Both users see each other's changes appear instantly, with no page refresh needed, and the system intelligently re-fetches only the affected table on any change event.

Two-user system with surgically scoped permissions:
Admin (Jeinna) — full access, all 6 tabs Limited (Greg) — locked to Payroll tab only

Greg can log new work entries and edit additional rate / notes fields, but cannot touch Summary, Database, or Billing records. Every action Greg performs is logged with a timestamp and visible to the admin via a bell icon — and only the specific field he changed turns bright yellow, never the whole row.

~90% fewer database reads than polling.

Built on Supabase Realtime WebSocket subscriptions rather than polling, the system re-fetches only the affected table on any change event — not all tables. This minimises egress significantly while keeping every view live.

Single-File SPA
No build tools or frameworks. The entire application ships as one HTML file with vanilla JS and CSS custom properties.
Realtime WebSocket
Push-based change notifications on every subscribed table — no polling. Auto-reconnects with 5-second backoff; falls back to 10-second polling if WebSocket unavailable.
Session-Based Auth
Role-aware authentication with 1-hour inactivity timeout and sessionStorage persistence. Users land back on the exact tab they were on after a refresh.
Paginated REST Fetches
HTTP Range headers bypass Supabase's hard 1,000-row API cap — supports unlimited historical data with seed fingerprint-based deduplication.
GitHub Pages Deployment
Drag-and-drop deploy with zero DevOps overhead. The application runs in production on free static hosting backed by a cloud database.
Egress Optimization
Targeted re-fetches on WebSocket events: idle = zero requests, entry saved = entries table only. ~90% fewer reads than the previous polling architecture.
Scroll Position Preservation
Double-requestAnimationFrame restore eliminates the scroll-jump issue common with innerHTML replacement. overflow-anchor: none prevents browser scroll-anchoring interference.
Fresh-State Logout
Every field, filter, report, and cached state is wiped clean on sign-out so the next session always starts blank — no leftover data from the previous user.

Six functional sections, one cohesive platform.

Each tab below is a complete workspace — with its own filters, inline editing rules, export options, and real-time data flow.

Dashboard
4 live stat cards (current month payroll, all-time payroll, active cleaner count, properties in database), recent entries table, top earners panel. Entries touched by the limited user are highlighted in yellow for admin visibility.
Log Work Entry
Structured form with auto-populating cleaner dropdown, property dropdown narrowed dynamically to the selected cleaner, and rate auto-fill from the database. Three work types: Cleaning, Inspection, Misc/Bonus. Form state preserved across tab switches.
Sorted Summary
Complete payroll record with 4 live filters (From Date, To Date, Cleaner, Property). Admin inline editing: date picker, rate override, additional rate, notes, delete. Greg's edits highlighted field-by-field in yellow. CSV export.
Employee Payroll Report
Per-cleaner pay-statement cards with active staff sidebar. Admin inline editing with confirmation dialogs. Manual pay row button for bonuses/adjustments. Bidirectional sync with Summary tab. Print/PDF and CSV export.
Billing System
Generates client-facing invoices grouped by property brand (Dream, Thomas, Dwellish, Lotus, Kinga, etc.). Misc items panel per group, running subtotals that update live, grand total card. CSV export includes billing table and all misc line items.
Database Editor (Admin Only)
Employee Rates, Billing Rates, and Add New tabs — view, filter, edit, delete, and add rate records, employees, and billing properties. Duplicate detection warns instead of silently creating a second copy.
Floating Chat (Messaging)
Private chat between users accessible from any tab via a floating bubble. Unread count badge, messages grouped by sender with timestamps, messages persist permanently in Supabase. Realtime-powered, no polling.
Activity Log & Change Tracking
Admin-only bell icon with unread badge. Logs every action by the limited user — new entries, rate overrides, deletions, manual pay rows. Mark All Read / Clear Log. Capped at 500 entries. Yellow highlight on edited fields only.
